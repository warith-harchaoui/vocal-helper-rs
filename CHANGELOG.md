# Changelog

All notable changes to `vocal-helper-rs` are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/), and the project adheres to
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `tests/jumeau_ami.rs`, ignored by default: 20 one-minute AMI clips transcribed
  from Rust and compared with the Python twin's transcripts, kept in
  `tests/fixtures/ami_jumeau_int8.json` and written by
  `scripts/make_ami_jumeau.py`. Needs `VH_NEMOTRON_ASR_GRAPH` and
  `VH_AMI_SUBSET`.

### Changed

- The transcription figures are re-measured (2026-11-05, Apple M2 Max, int8):
  4.4 % WER from the Python twin over 20 min of AMI, not 0.86 % (that figure
  came from one minute). The gap is the int8 graph's noise floor, not the Rust
  host: the log-mel matches to 1.3e-6, the Python twin fed the Rust log-mel
  still disagrees on the same frames, and the Python twin against itself with
  graph optimizations off is 4.4 % apart too. RTF is 0.05 on CPU, against
  0.022 to 0.028 for the Python twin; the 0.15 of 0.1.0 was not reproduced.

## [0.1.0] - 2026-11-04

First release: the free local Nemotron paths of the Python `vocal-helper`,
end to end from Rust.

### Added

- **Streaming diarization with Nemotron 3** (`diar_session::NemotronDiar`,
  feature `onnx`): the file streams chunk by chunk through the ONNX graph while
  the speaker cache and FIFO are kept between steps. Per-frame probabilities
  match the Python twin to within 2e-6 on AMI (1.9e-6 over one minute,
  re-measured for this release), cache compression included.
  `examples/diarize.rs` diarizes a WAV.
- **Transcription with Nemotron 3.5** (`asr_session::NemotronAsr`, feature
  `onnx`): 30 s windows, greedy CTC, timed words, speaker and event tags. Text
  is within 0.86 % WER of the Python twin on the int8 graph.
  `examples/transcribe.rs` transcribes a WAV.
- The pure parts, all tested without a model and against fixtures generated by
  the Python twin: the log-mel front end (`mel`), the speaker-cache and FIFO
  bookkeeping (`cache`), the streaming schedule and its two ceilings
  (`schedule`, now read from the graph's metadata), per-frame probabilities to
  speech turns (`segments`), the NeMo ASR host (`asr`), and a reader for a
  graph's `metadata_props` that does not load its weights (`onnx_meta`).
- `accel`: the policy that picks an execution provider from timings taken on
  the device, keyed to a graph digest. It is not wired into the sessions yet:
  both open their graph on ONNX Runtime's CPU default.

### Notes

- Rust 1.82 without `onnx`; 1.92 with it, the floor of `ort` 2.0.0-rc.15.
  `ort` is pinned exactly, because its API changes between release candidates.
- The graphs are not shipped with the crate: callers pass their path.
